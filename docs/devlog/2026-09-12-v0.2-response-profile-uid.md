# FromISH · 响应提醒、协作画像与顺序 UID（2026-09-12）

## 问题与原因

发起人虽然能在「我的项目 → 回应中心」看到待处理数，但顶部导航没有对应反馈，别人回咩容易被漏看。响应中心已有技能和自述经历，尚未展示用户明确选择的喜好、介绍缺失时的说明及当前公开同行履历；团队页只有通往公开个人资料的链接，遇到未打开公开开关的用户就看不到同行必需的自述信息。页面暴露的 UUID 很长，也不适合口头沟通或查找账号。

## 本轮修改

- 「我的项目」顶部徽标汇总待回应申请、自己回应的新处理结果和原有同行核查提醒。提交响应时，数据库同一事务向发起人写站内消息；点击消息直接到回应中心的那条申请。撤回或处理后待回应计数随当前状态更新。
- 申请审核中的响应者显示当前填写的介绍、技能、明确选过的喜欢与不喜欢的方向、经历/试玩、作品链接、其他仍有效的公开项目同行履历及短 UID；这些都是本人自述，没有能力认证。已经成为 ACTIVE 同行者的人在团队页可由当前发起人和当前同行成员查看同样的资料；失效的响应（撤回、婉拒或被移出）不再从申请卡展示非公开画像，被移出者也不能进入团队页。
- 提交按钮旁说明共享范围；个人画像中的「公开」明确指向所有访问者的全站公开。主动响应会向那个项目的发起人披露当前画像；接受后向当前团队披露，与全站公开开关独立。系统推测的弱偏好、邮箱与账户处分不会共享到团队画像。
- User 新增唯一整数 `uid`：迁移时锁住用户表，按 `createdAt,id` 给旧账户从 1 编号，再设置自增序列；内部 UUID 仍作为所有外键、权限、申诉与审计日志的主键，也维持原站主环境变量。公开用户页和举报支持 UID 及历史 UUID 路径；个人页、创作者资料链接和网站用户治理检索优先显示 UID；首次配置站主仍可从个人页折叠区取得 UUID。

## 取舍与边界

UID 是公开可记的号码，不是身份认证凭据、权限凭据或秘密；不会被重用。原有链接兼容 UUID，避免断开旧通知。名单中的“同行经历”只读正在同行且公开发布的项目；本人填写的试玩经历不被系统当作已核实事实。短 UID 可被枚举，因此普通资料页依然遵守全站公开开关，不因号码变短自动公开隐藏画像。只有相关项目发起人或当前有效成员才读取和展示协作场景资料。

## 验证与未来方向

校验 Prisma schema、迁移 SQL 与模型差异、类型和生产构建，并把本轮增量补丁在上一轮补丁基线上试应用。这里不连接用户 Windows 本地数据库；迁移后应由三个真实账号分别检查旧账号 UID、新注册 UID 递增、提交/撤回回应、发起人消息定位、未开公开开关时的申请与团队资料、被移出后的团队权限。验收通过后再提交 `feature/v0.2-meow` 供审阅。

未来在表单里可加“申请时分享资料预览”，并研究画像更新后的提醒与更细粒度的协作可见性。项目内部论坛/公告和权限仍依既定路线推进，公开注册前还要做验证与抗自动化策略。
