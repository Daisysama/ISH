# 2026-09-12 · 移出申诉表单与提醒

开发者：Codex；基线：Lysander 已收到的移出可见性与独立复核补丁。

## 本次目标

修复仅填写申诉说明时出现的“申请内容不完整”，并让新申诉及处理结论在对应角色的页面有可见提醒。

## 做了什么、改了什么

- 原因：表单把“主要问题”设为必选，但界面只在说明字段加星号；服务端把空分类和失效隐藏字段合并为一句含糊的错误。现在分类可跳过，空值按“其他”记录；申诉说明仍必须有 10～2000 字，非法选项及失效记录各有具体提示。
- 新增仅按本人权限统计的提醒：发起人可见发给自己的待核查数，独立网站管理员可见自己能处理的平台待审数，申请人可见尚未查看的处理结果数；平台申诉内容和数量不向项目发起人披露。
- 导航和项目审核页的独立申诉入口显示待办数量，工作台为发起人及申请人提供项目直达链接；用户进入本人项目的复核页后，该项目已显示的结果才记为已看。处理结论、原始申诉与审查事件均不因已读而改动。
- 新增增量 migration 和查询索引，并更新文件职责地图。

## 设计思路及权衡

文本本身足以提交申诉，分类仅用于帮助审理，不让额外选择挡住求助。提醒采用页面计数和本人已读状态，不引入邮件、推送或即时消息基础设施；重新访问页面时计数更新。管理员有利益冲突的案件不计入其可处理数，但仍留在审核页供移交。

## 影响与权限

- 前端：申诉表单、全局导航、我的项目、本人申诉详情、少量样式。
- 后端：按本人及角色隔离的申诉计数、链接查询与已读动作。
- 数据库：`project_removal_reviews.appellantDecisionSeenAt` 可空字段及索引；旧的已处理案件初次升级时按“未看”提醒一次。
- 权限：已读仅本人可修改自己的处理结果；发起人不能读到平台申诉的说明或其待处理数；平台管理员不可裁决本人或自己项目的案件。

## 验证

- `npm run db:generate`、`npm run typecheck`、`npx prisma validate`、`npm run build`。
- 仍需在用户的 Windows 本地数据库运行新增 migration，并用三个独立账号验证：空分类 + 合格说明可提交；空说明 / 少于 10 字应提示；发起人和管理员只看到各自提醒，平台处理后申请人看到新结果，打开对应申诉页后提醒清除。

## 已知问题与后续方向

目前没有实时推送或统一通知收件箱；提醒在下一次页面请求时更新。旧版已处理申诉在升级后会出现一次新结果提示。下一步按原计划完善持续监管（全项目视图、退回修改、下架/恢复），之后逐步建立 OWNER / ADMIN 权限与可视化治理日志，再补署名纠正、勘误及更完整的二审和证据保全。
