# 2026-09-08 · v0.1-alpha public release

## 任务
将 ISH 当前最小可用版本部署到 `fromish.com`，作为第一个可公开访问的 Alpha。

## 当前范围
- 用户注册
- 用户登录
- 用户登出
- 登录后的工作台占位页

暂不加入发愿、结伴、立契、同行、邮箱验证码、微信绑定等业务功能。

## 为什么这样做
先验证最小闭环能否在真实公网环境稳定运行：浏览器 -> HTTPS -> Web 应用 -> PostgreSQL -> 会话 Cookie。
避免在基础设施和账号体系尚未稳定时同时增加大量业务逻辑。

## 部署思路
- CVM 只公开 80/443；22 仅可信 IP。
- Next.js 只监听 `127.0.0.1:3000`，不直接暴露公网。
- Nginx 负责反向代理、HTTPS 和登录/注册入口的基础限速。
- PostgreSQL 仅允许应用安全组通过 VPC 访问 5432。
- 生产环境使用独立数据库运行账号，不长期使用超级管理员账号。
- systemd 管理 Next.js 进程，异常时自动拉起。

## 已知限制 / 风险
- 当前邮箱不验证真实性，公开后可能产生垃圾账号。
- 当前尚无应用层细粒度限流与风控，Nginx 只提供第一层保护。
- 当前数据库结构使用 `prisma db push`，在积累重要数据前应切换为可审计的 Prisma migrations。
- 用户密码长度目前按字符限制；后续应将 bcrypt 的 72-byte 限制检查改为按 UTF-8 字节数判断。

## 后续方向
1. 生产监控与错误日志。
2. 邮箱验证 / 找回密码。
3. 注册与登录的应用层限流。
4. 微信等外部账号绑定。
5. 第一项真实业务能力。
