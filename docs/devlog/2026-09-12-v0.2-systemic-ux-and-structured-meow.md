# 2026-09-12 · v0.2 产品系统性 UX 与结构化「咩」

## 本次目标

在第一条“咩 → 审核 → 发布”闭环已经验收通过后，修复 UI 现场测试暴露出的产品系统性问题，并降低创作者首次发布项目的输入成本。

本次集中解决两个问题：

1. 不同页面各自设计导航，导致“羊群广场 / Dashboard / 审核 / 项目详情”之间的返回位置漂移，用户需要重新寻找入口；
2. 第一版“咩一个”要求用户连续填写多段长文本，发布成本过高，也无法让玩家在项目卡上快速判断项目类型和需要什么同行者。

## 做了什么

### 1. 统一 Global Header

建立统一全局导航：

- FromISH 标识固定在左上；
- 羊群广场；
- 咩一个；
- 我的项目（登录后）；
- 审核（仅管理员）；
- 账号区域固定在右侧。

审核页、项目详情、咩页面不再自己重新设计顶部导航。

页面内部需要返回上级时，使用正文区域的 breadcrumb，例如：

`← 我的项目`

它不再替代全局导航。

### 2. 「咩一个」结构化

将原先“标题 + 一句话 + 长项目说明”的输入方式改为：

- 项目名称；
- 一句话介绍；
- “咩咩啊？”项目类型标签；
- 项目当前阶段；
- “想找什么样的羊？”角色 / 技能标签；
- 目标平台；
- 已有作品 / Demo 外链；
- 群聊类型和联系方式；
- 是否欢迎 ISH 加入群聊；
- 可选补充说明。

项目类型和招募标签都允许创作者追加少量自定义标签。

### 3. 羊群广场卡片增加信息密度

玩家无需点进详情页即可看到：

- 项目当前阶段；
- 项目类型标签；
- 正在寻找的角色 / 技能标签。

标签过多时只显示前三个并用 `+N` 收起，避免卡片失控。

### 4. 群聊与 ISH 陪伴

群聊信息默认不公开展示在项目卡或公共详情中，仅创作者和 ISH 管理员可见。

创作者可以主动勾选：

`欢迎 ISH 加入群聊`

说明文案明确：ISH 也许会加入群聊了解项目情况，在需要时提供帮助并陪伴项目成长。

采用产品承诺：

> ISH 不只帮你发声，也愿意陪你往前走。

并保留小型品牌彩蛋：

`We + ISH = WISH.`

## 有意没有做的事情

### 图片上传暂不混入本次补丁

产品已经确认需要“上传概念图 / 截图 / 草图”，但真正的上传意味着新增：

- 文件存储位置；
- MIME 与尺寸校验；
- 图片重编码 / EXIF 清理；
- 生产服务器目录权限；
- 备份与删除策略；
- 未来对象存储迁移。

因此本次不做一个“看起来能上传但生产不可维护”的假功能。

图片上传作为紧接着的独立子阶段实现，并在接入前明确香港单机服务器上的持久化方案。

## 设计原则

### 位置记忆属于产品能力

页面可以漂亮，但不能让用户每换一页就重新寻找导航。

### 功能必须清楚，但表达不必无聊

“咩咩啊？”可以负责性格，下面的“选几个标签，让羊群一眼知道你在做什么”负责理解。

### 没有功能，就不要伪装成功能

本阶段不使用假的搜索、点赞、项目数字或图片上传入口。

10. 在羊群广场、Dashboard、咩页面、审核页、项目详情之间跳转，Global Header 的位置和导航顺序保持一致

## 本地 Migration 后 Prisma Client 同步热修

在首次应用 `20260912080000_structured_meow` 后发现：数据库 migration 已成功，
但直接执行 `scripts/migrate-local.ps1` 不会重新生成 Prisma Client，导致 TypeScript 仍按旧版 schema 推导 `Project` 类型，出现 `stage`、`typeTags`、`seekingTags`、`platforms` 等字段“不存在”的连锁报错。

这不是 migration 失败，而是数据库结构与本地生成的 Prisma Client 不同步。

### 修复

- `scripts/migrate-local.ps1` 在 migration 成功后统一执行 `npm run db:generate`；
- `scripts/setup.ps1` 不再重复生成 Client，只依赖 `migrate-local.ps1` 完成“迁移 + Client 同步”；
- 因此无论开发者执行一键 setup，还是单独执行本地 migration，Prisma Client 都会与当前 `schema.prisma` 保持一致。

### 当前环境恢复

已经成功应用 migration 的环境无需重建数据库，只需先执行：

`npm run db:generate`

再重新执行 `npm run typecheck` 与 `npm run build`。
