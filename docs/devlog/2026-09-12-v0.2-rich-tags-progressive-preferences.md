# v0.2 Rich Tags & Progressive Preferences

日期：2026-09-12

## 做了什么

- 将项目官方标签扩展为分组标签库，覆盖类型玩法、游玩模式、关系受众、题材氛围、美术表现、机制体验；
- 保留并增强自定义标签，自定义输入在前端即时生成 Chip；
- 画像页使用同一套兴趣标签语义，并扩充技能 / 工具标签；
- 新增私人“感兴趣 / 不感兴趣”项目偏好；
- “不感兴趣”后隐藏项目；
- 点击项目偏好时允许选择具体元素，也允许跳过或以后不再询问；
- 新增弱推断标签信号，与用户显式画像分开；
- 画像页允许查看并删除系统推断标签；
- 推荐排序开始参考弱推断信号，但权重低于显式偏好；
- 面向用户的相关文案统一使用“您”。

## 为什么改

注册和画像必须保持低门槛，但推荐不能永远停留在“一次性问卷”。用户正常浏览项目时产生的轻量行为，应该逐渐改善体验，同时不能反过来形成持续打扰。

标签库也不能只靠平台预先猜测。官方标签解决常见语义，自定义标签承接长尾；后续再根据真实使用频率维护官方标签库。

## 数据设计

- `ProjectPreference`：用户对单个项目的私人兴趣 / 隐藏状态；
- `UserTagSignal`：系统根据行为得到的弱标签信号；
- `User.likeTags / dislikeTags`：继续表示用户明确表达的偏好；
- `suppressInterestedPrompt / suppressNotInterestedPrompt`：记录用户是否关闭追问。

## UI 复核：偏好可逆与监管隔离

现场测试发现，“不感兴趣”一旦提交便立即从羊群广场消失，误触后缺少反悔路径。
本次将“不感兴趣”和“隐藏”拆开：前者默认只记录私人推荐信号，后者必须由用户明确选择；当前选择也可以再次点击撤销，隐藏项目可以在画像页恢复。

同时明确：用户的私人隐藏列表只作用于自己的发现流，管理员监管查询不读取这些偏好条件，不能因为任何用户点击“不感兴趣”产生监管盲区。

首页 Hero 中的 `A small light. / A larger tomorrow.` 装饰文案也一并移除，进一步减少不必要的概念图式装饰。
