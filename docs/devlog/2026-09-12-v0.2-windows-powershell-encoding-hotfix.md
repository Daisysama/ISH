# Windows PowerShell 空白检查脚本编码修复（2026-09-12）

## 问题与原因

在 Windows PowerShell 5.1 执行 `scripts/check-whitespace.ps1` 时出现乱码和解析错误。此前脚本用无 BOM 的 UTF-8 保存了中文注释与字符串；Windows PowerShell 5.1 可能使用本地代码页解码该文件，使字符串边界被错误解析。执行失败时没有开始 Git 检查，也没有更改源码或数据库。

## 本次修改与思路

- 将 `scripts/check-whitespace.ps1` 的注释和反馈改为纯 ASCII，保持原有 Git 检查命令与失败时返回错误的行为；不依赖用户的终端代码页或修改全局编码设置。
- 工作区的 `git diff --check` 仍只检查未暂存的更改；需要检查暂存区时，另行运行 `git diff --cached --check`。
- 文件位置和作用仍见 `docs/architecture/FILE_MAP.md`；本文件记录此轮故障原因、修复与交接。

## 验证与交接

验证脚本内容仅含 ASCII 字节，并检查热修复补丁可以在上轮交付的文件版本上无冲突应用；在本环境无法执行 Windows PowerShell 5.1，需在用户的 Windows 本机再次运行 `./scripts/check-whitespace.ps1` 验收。

## 后续方向

新建 PowerShell 脚本时默认使用纯 ASCII，确需中文字符串时显式采用兼容 Windows PowerShell 5.1 的编码；继续逐步规范仓库的 Git 换行设置，避免 LF/CRLF 转换提示干扰检查。
