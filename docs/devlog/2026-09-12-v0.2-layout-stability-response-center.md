# v0.2 Layout Stability & Response Center

## 做了什么

1. 为 `html` 启用 `scrollbar-gutter: stable`，让长页面与短页面都预留稳定的滚动条空间。
2. 把 Dashboard 顶部的“回应我的咩”统一为“回应中心”，去掉“我同行的”区域重复的回应中心入口。
3. 回应中心提示分成两类：
   - 创作者尚未处理的 `PENDING` 响应；
   - 响应者尚未看过的 `APPROVED / REJECTED` 结果。
4. 新增 `ProjectResponse.responderDecisionSeenAt`。进入回应中心后，已处理结果自动标记为已读。

## 为什么改

- `/projects`、`/meow/new` 内容较长时浏览器出现纵向滚动条，而 `/dashboard`、`/admin/moderation` 内容较少时滚动条消失。居中容器会因此改变可用视口宽度，导航和主体产生横向跳动，削弱整体质感。
- “回应我的咩”和“回应中心”实际上指向同一套业务，不应在同一个 Dashboard 里形成两个像不同功能的入口。
- 只有待处理数量不足以提醒响应者创作者已经接受 / 婉拒，需要有可清除的“新结果”状态。

## 设计取舍

- 待处理的 incoming response 在创作者真正接受 / 婉拒之前一直计数；单纯打开回应中心不会把它伪装成“处理完了”。
- outgoing decision 只有 `APPROVED / REJECTED` 且尚未看过时计数；用户进入回应中心后标记已读。
- 历史 Alpha 数据在 migration 中回填为已读，避免升级后突然出现大量伪“新消息”。
- 当前不引入通用 Notification 表；等评论、论坛、举报、成员权限等更多通知源上线时，再升级成统一通知中心。

## 未来方向

- Community Layer 上线前建立通用通知模型，覆盖评论回复、@、举报处理、项目版本审核、成员权限变化。
- Global Header 后续可显示统一通知入口，而不是为每类业务单独堆 badge。
