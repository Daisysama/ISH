# FromISH · ISH 公告编辑、删除与站主恢复（2026-09-12）

## 为什么改

原公共公告页在「删除」后仍显示撤回占位，甚至提示旧内容保留在后台；右侧的编辑和删除展开成竖向表单，既抢占公告宽度，也不符合用户希望的直接操作。编辑后留在原卡片里，缺少完整的独立编辑页面。管理页只列最近 50 条，较早删除的公告可能没有恢复入口。普通读者的公告也被空的管理栏挤窄。置顶排序依赖数据库对空时间的默认排序，未明确保证置顶公告排在最前。

## 做了什么、改了什么

- 公共页只查询 `PUBLISHED`：点「删除」后公告从公共页消失，不显示已删除卡片、占位或处理理由。删除按钮无需填写说明；站主或有公告发布权限的原作者可操作。
- 公共公告右侧保留同风格的「编辑」「删除」「置顶 / 取消置顶」三个紧凑操作，宽度最多 240px；只有可操作本人公告的人员看得到。普通读者没有空白工具栏。编辑进入 `/admin/announcements/[id]/edit`，草稿和公开版均核查服务端权限；公开版仍须写修改原因并保留旧版本。
- 删除采用已有 `WITHDRAWN` 状态，不物理删除原文；在一个事务中更新状态、解除置顶并追加 `DELETED` 事件与内容快照。若管理员删除，向站主发送站内提醒。管理页将已删除记录放在站主可用的分页列表中；站主点击恢复时追加 `ANNOUNCEMENT_RESTORED` 事件并恢复公开，不清除原来的删除事件，且不冒充新发布或自动置顶。
- 置顶排序明确使用 `pinnedAt DESC NULLS LAST`，多则置顶时以最近一次置顶的时间排前，非置顶再按原发布时间排列。置顶和取消置顶保留事件。
- 站主「网站治理」增加到公告操作记录的入口；管理页保留原文和事件理由；中文事件标签和文件地图同步更新。

## 思路与边界

「公共页不留痕迹」指删除后不再给普通用户展示公告条目；站主恢复能力与内部可追溯要求意味着数据库仍需保留原文和事件，不能硬删除。管理员只能删除或修改自己的公告，站主可处理任意公告；恢复权只给站主，服务端再次核查。现有 `WITHDRAWN` 记录也可由站主恢复，以兼容旧的撤回数据。本轮复用现有 Prisma 模型和迁移，无新增表或数据库迁移。
