# v0.2 B.2a-1：项目发现、用户画像与 SEO Foundation

日期：2026-09-12

## 做了什么

在结构化“咩”基础上增加项目发现四轴中的两个新轴：发布目的与主要受众；增加群聊开放策略；增加自愿填写的用户技能 / 兴趣 / 雷点画像；增加羊群广场基础筛选与透明推荐；建立 robots、sitemap、canonical 与 Open Graph 基础。

## 为什么改

仅靠“项目类型 + 成熟度”不足以表达同一声咩是在找合作伙伴、邀请玩家试玩还是单纯宣传；群号也不能统一按私密信息处理，因为宣传型项目可能希望直接公开。

同时，注册门槛不应因推荐系统提高。因此画像后置、可跳过，技能与经历明确标注为用户自述、未经 ISH 认证。

## 关键设计

- `ProjectPurpose`：COLLABORATE / PLAYTEST / FEEDBACK / PROMOTE / SHARE。
- `ProjectAudience`：EVERYONE / COLLABORATORS / PLAYERS；当前用于推荐，不做硬访问控制。
- `GroupAccessMode`：PUBLIC / APPROVAL_REQUIRED / PRIVATE。
- 申请制群聊的数据模型先建立，但 UI 暂不开放选择，避免伪装尚未实现的同行申请功能。
- 用户画像字段为 skillTags / likeTags / dislikeTags / profileBio / experienceText / portfolioUrl。
- 默认推荐只采用标签匹配、技能匹配、目标受众和新鲜度等可解释信号。
- 雷点仅降低推荐权重，不阻止主动搜索。
- Sitemap 只包含首页、羊群广场与 `PUBLISHED` 项目。

## Sitemap 构建期数据库依赖热修

UI / SEO 验收时发现：`src/app/sitemap.ts` 在 `next build` 阶段被预渲染，
因此构建机若没有正在运行的 PostgreSQL，会在生成 `/sitemap.xml` 时直接导致整个生产构建失败。

### 修复

- 将 sitemap 明确设为动态运行时生成：`dynamic = 'force-dynamic'`；
- 将 `revalidate` 设为 `0`，避免构建期预渲染依赖数据库；
- 搜索引擎真正访问 `/sitemap.xml` 时，再从数据库读取最新 `PUBLISHED` 项目。

### 原则

生产构建应尽量验证代码和静态资源本身，而不应因为本地 / CI 数据库暂时离线就无法完成。
动态业务数据由运行时路由负责读取。

本修复不改变 sitemap 的公开范围：仍只包含首页、羊群广场和已发布项目。
