# FromISH 导航与移动端原则

## 1. 一级页面靠稳定主导航，不伪造“上一级”

羊群广场、咩一个、我的项目、审核等属于同级产品入口。

这些页面不因为某次访问路径不同，就额外制造“← 我的项目”之类的假父子关系。用户通过稳定的 Global Header 在一级页面之间切换。

## 2. 二级详情页必须记得用户从哪里来

项目详情是二级页面，应该提供持续可见的上下文返回。

- 从羊群广场进入：返回羊群广场。
- 从我的项目进入：返回我的项目。
- 从回应中心进入：返回回应中心。
- 从审核进入：返回审核。
- 从首页或个人资料进入：返回对应入口。
- 直接分享 / 搜索进入，没有可信来源时：默认返回羊群广场。

来源只能使用站内白名单标识，不接受任意外部 URL，避免开放重定向。

原则：**哪里来的，就尽量回哪里；没有来源，才给稳定默认出口。**

## 3. 长页面不能把出口留在用户身后

项目详情的上下文返回条保持 sticky。PC 可辅助展示当前项目名；移动端只保留返回动作，避免挤占横向空间。

## 4. Mobile 不是 PC 的缩小版

FromISH 的高频消费场景很可能发生在手机上，因此核心功能必须同时设计 Desktop 与 Mobile。

每个核心页面至少检查：

- 390px 左右宽度是否仍能完成主要任务；
- 操作按钮是否足够大且不挤成小字链接；
- 关键操作是否需要横向滚动；
- sticky 元素是否遮挡正文；
- 长表单错误是否能直接定位；
- 卡片主要动作是否适合单手点击；
- PC 新增能力是否在移动端拥有等价入口。

未来小程序和 App 可以复用相同的信息架构与动作语义，而不是重新定义一套产品逻辑。
