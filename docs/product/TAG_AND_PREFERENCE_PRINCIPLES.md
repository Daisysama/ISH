# FromISH 标签与偏好学习原则

## 1. 标签要丰富，但不要把复杂度甩给用户

FromISH 使用“官方标签库 + 用户自定义标签”的双层结构。

- 官方标签压缩为“类型与玩法 / 游玩方式 / 题材与风格 / 关系与受众”四组，减少重复分类；
- 发布项目和填写画像时，用户可以直接选择官方标签；
- 没有找到合适标签时，可以输入文字并用逗号 / 回车快速生成自定义标签；
- 高频、稳定、语义明确的自定义标签，未来可以由管理员提升为官方标签；
- 不使用“正常向”等可能暗示其他创作方向“不正常”的标签，统一采用“一般向 / BG / 百合 / BL”等中性表达。

## 2. 低下限，高上限

刚有一个点子的人，不需要为了“标签完整”才能发出一声咩；成熟团队则应该有足够丰富的标签表达自己的作品。

默认界面优先展示常用分组，其余分组可以展开。自定义标签永远是兜底入口。

## 3. 平台要懂人，但别烦人

“感兴趣 / 不感兴趣”首先是用户自己的推荐工具，不做公开点赞排名。

- 用户点击“感兴趣”时，可以补充具体喜欢哪些项目元素；
- 用户点击“不感兴趣”时，可以补充具体不喜欢哪些元素；
- 两个面板都允许直接跳过；
- 两个面板都允许选择“以后不再弹出”；
- 用户明确选择的标签属于显式偏好；
- 仅根据一次项目点击推断出来的标签只属于弱信号；
- 显式偏好永远优先于系统推断；
- 用户可以在“我的画像”里删除系统猜错的弱偏好，并重新开启或关闭追问。

一句话：**FromISH 可以越来越懂您，但不该越来越烦您。**

## 4. “不感兴趣”不等于封锁世界

对单个项目选择“不感兴趣”只记录私人推荐信号，不自动隐藏。

对某个标签表达“不喜欢”，只降低相关推荐权重，不禁止用户以后主动搜索和访问该类内容。

## 5. 私人信号与公开评价分离

本阶段的“感兴趣 / 不感兴趣”是私人推荐信号：

- 不公开全站计数；
- 不影响项目公开评价；
- 不把“感兴趣”包装成社区投票；
- 公开“种草”、评论和制作人回复留到 Community Interaction 阶段，与内容治理一起上线。

## 不感兴趣与隐藏必须分开

“不感兴趣”是私人推荐信号，不等于删除项目，也不应该让卡片在一次误触后立刻消失。

- “不感兴趣”默认只降低推荐权重；再次点击可以撤销。
- 如果用户明确希望眼不见为净，可以额外选择“隐藏这个项目”。
- 隐藏项目必须可恢复，并集中展示在“我的画像”里。
- 用户的私人偏好、隐藏列表和推荐算法永远不得影响管理员的全站监管视野。

一句话：**推荐可以因人而异，监管不能留下盲区。**


## 6. 隐藏是一条独立的路

“隐藏项目”不依赖“感兴趣 / 不感兴趣”弹窗，也不依赖用户是否关闭偏好追问。

- 用户任何时候都可以单独隐藏一个项目；
- 隐藏前给出轻量确认，避免误触；
- 隐藏后当前页面提供撤销入口；
- “我的画像”集中展示隐藏项目并允许恢复；
- 隐藏记录与偏好记录分开存储，避免语义耦合；
- 管理员监管查询永远不读取用户私人隐藏列表。
