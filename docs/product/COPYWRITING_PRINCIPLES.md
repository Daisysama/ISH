# FromISH 文案原则

## 核心原则

> **功能必须清楚，但表达不必无聊。**

FromISH 面向创作者、玩家和同行者。前台表达应当有生命力、有画面感，但不能为了玩梗牺牲功能理解。

## 五条规则

1. **先让人看懂，再让人记住。**
   - 用户必须先知道按钮会做什么、页面是什么，再谈品牌性格。
2. **能有性格，就不要写成后台文案。**
   - “创建项目”可以表达为“咩一个”；“项目广场”可以表达为“羊群广场”。
3. **活泼不等于幼稚。**
   - 欢快、有梗、有诗意，但不过度卖萌，不降低专业创作者的信任感。
4. **品牌文化服务于用户体验。**
   - 羊群、太阳、同行者可以成为产品意象；企业内部治理口号不直接占据产品首屏。
5. **不同场景使用不同语气。**
   - 首页、空状态、活动页可以活泼；审核、隐私、协议、错误信息必须准确克制。

## 当前 Alpha 主文案

- 首页：**有点子？上伊始！找乐子？也上伊始！**
- 羊群广场：**加入羊群，一起追逐太阳！**
- 空状态：**第一声咩还在路上。**
- 创作入口：**请把您的梦，咩出来！**

## 视觉与品牌边界

当前公开 Alpha 使用“灵光初现 / First Glimpse”弃稿中的抽象线形星芒作为 FromISH Alpha Mark。

- 网站：浅底版；
- 社交媒体：深底版；
- 伊始蛋与正式“灵光一闪”继续作为未公开核心品牌资产。

Alpha Mark 只承担产品验证阶段的公共识别，不代表最终正式商标或最终品牌 Logo。

## 产品系统性补充：位置记忆优先于页面自由发挥

FromISH 的页面可以有不同气质，但全局导航必须保持稳定。用户不应该在页面之间移动时重新寻找“回去”的按钮。

- 普通产品页统一使用 Global Header；
- FromISH 标识始终位于左上角并可返回首页；
- `羊群广场 / 咩一个 / 我的项目 / 审核` 使用稳定顺序；
- 账号区域始终位于右侧；
- 页面内部的“返回”只作为 breadcrumb，不替代全局导航；
- 可以做漂亮的页面，但不能让用户重新学习每一页怎么回去。

内部原则“功能必须清楚，但表达不必无聊”只用于产品与设计决策，不直接作为网站宣传文案展示给用户。

## 交互原则：平台要懂人，但别烦人

FromISH 会努力理解每一位同行者的兴趣，但不会追着大家填表做题。

- 能从行为里看懂的，就不反复追问；
- 能少问一句的，就少问一句；
- 能让人舒服一点的，就别让人多点一步；
- “感兴趣 / 不感兴趣 / 收藏 / 跳过”等行为都可以帮助系统慢慢理解偏好，但只能作为轻量信号；
- 用户明确说过的喜欢与不喜欢，优先级永远高于系统自己的猜测；
- 用户可以随时修改、删除偏好，也可以选择“以后不再弹出”；
- 系统可以主动学习，但不能偷偷替用户下结论，更不能因为一次点击就给人贴死标签。

一句话：**FromISH 可以越来越懂您，但不该越来越烦您。**

## 称呼原则：尊重，但不要像柜台

FromISH 面向用户的系统文案默认使用“您”。能自然省略人称时可以省略，避免为了礼貌把文案写得生硬。

- 推荐：“ISH 不只帮您发声，也愿意陪您一起走。”
- 推荐：“您不需要先写一份企划书。”
- 不推荐：同一页面一会儿“你”、一会儿“您”。

尊重用户，不等于把 FromISH 写成银行柜台；活泼、轻松和礼貌可以同时存在。


## 交互原则补充：少打扰，不等于少给路

用户关闭偏好追问，只代表不希望再被弹窗打扰，不代表放弃控制项目显示方式。

- “感兴趣 / 不感兴趣”只负责推荐信号；
- “隐藏项目”是独立、长期可用的操作；
- 隐藏必须可撤销，并能在“我的画像”中恢复；
- 关闭追问后，也可以在“我的画像”重新开启；
- 私人隐藏永远不能影响管理员的全站监管视野。

一句话：**用户不想被打扰，不等于用户放弃控制权。**
